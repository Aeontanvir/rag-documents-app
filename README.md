# Doc AI

Document ingestion and RAG application built with a FastAPI backend and a React frontend.

It lets a user:

- upload documents such as PDF, DOCX, TXT, Markdown, HTML, and CSV
- chunk them into retrieval-friendly context
- store embeddings in ChromaDB
- ask grounded questions against the indexed documents from a simple web UI

## Architecture

The project is split into two main parts:

- `backend/`
  FastAPI application for document ingestion, chunking, vector storage, and question answering.
- `frontend/`
  React + Vite application for uploading files, listing indexed documents, and sending prompts.

### High-level flow

1. A user uploads one or more documents from the React UI.
2. The FastAPI backend saves the files under `backend/storage/uploads/`.
3. LangChain document loaders parse the files into raw document sections.
4. A recursive chunking pipeline normalizes text and splits it into context-aware chunks.
5. Embeddings are generated by the configured embedding provider.
6. Chunks and embeddings are stored in ChromaDB under `backend/storage/chroma/`.
7. A user asks a question from the frontend.
8. The backend retrieves relevant chunks from ChromaDB and sends the context to the configured chat model.
9. The answer and supporting chunks are returned to the frontend.

## Frameworks And Libraries

### Backend

- `FastAPI`
  Used to expose REST endpoints for health checks, document upload, document listing, deletion, and RAG querying.
- `LangChain`
  Used as the orchestration layer for document loading, text splitting, embeddings, vector retrieval, and LLM calls.
- `langchain-community`
  Used for open-source document loaders such as PDF, DOCX, TXT, Markdown, HTML, and CSV loaders.
- `langchain-text-splitters`
  Used for recursive chunking with separator-aware splitting.
- `langchain-chroma`
  Used to connect LangChain documents and retrieval logic to ChromaDB.
- `ChromaDB`
  Used as the local persistent vector database.
- `langchain-ollama`
  Used when the project is configured to run with local Ollama models.
- `langchain-openai`
  Used when the project is configured to run with OpenAI-compatible APIs.
- `pydantic-settings`
  Used for environment-based application configuration.
- `python-multipart`
  Used for file uploads in FastAPI.
- `unstructured`, `pypdf`, `docx2txt`
  Used to parse and extract text from multiple document types.

### Frontend

- `React`
  Used to build the upload, document list, and prompt/answer UI.
- `Vite`
  Used as the frontend development server and build tool.
- `React DOM`
  Used to render the React application in the browser.

## Chunking Strategy

The ingestion pipeline uses an open-source, context-aware chunking process:

1. Parse the source file into document sections.
2. Normalize whitespace and remove noisy formatting artifacts.
3. Add lightweight context like filename and page number to each section.
4. Split text with `RecursiveCharacterTextSplitter`.
5. Prefer meaningful boundaries in this order:
   headings, paragraphs, line breaks, sentences, words.
6. Apply chunk overlap so context survives retrieval boundaries.

This is stronger than fixed-width slicing and keeps the pipeline simple and open source.

## Installation

### Prerequisites

- Python 3.9+
- Node.js 18+
- npm

You also need one model provider:

- `Ollama` for fully local models, or
- an `OpenAI-compatible API key`

### 1. Clone and enter the project

```bash
cd /Users/aeon/Documents/Workstation/practices/doc-ai
```

### 2. Install backend dependencies

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### 3. Configure the model provider

#### Option A: Ollama

Default `.env` already points to Ollama:

```env
LLM_PROVIDER=ollama
LLM_MODEL=llama3.1:8b
EMBEDDING_PROVIDER=ollama
EMBEDDING_MODEL=nomic-embed-text
```

Install and prepare Ollama:

```bash
ollama serve
ollama pull llama3.1:8b
ollama pull nomic-embed-text
```

#### Option B: OpenAI-compatible API

Edit `backend/.env` to:

```env
LLM_PROVIDER=openai
LLM_MODEL=gpt-4o-mini
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-large
OPENAI_API_KEY=your_api_key
```

If needed, you can also set:

```env
OPENAI_BASE_URL=https://your-compatible-endpoint
```

### 4. Install frontend dependencies

```bash
cd /Users/aeon/Documents/Workstation/practices/doc-ai/frontend
npm install
```

Backend URL:

```bash

npm run dev -- --host 127.0.0.1 --port 5173
```

Frontend URL:

- [http://127.0.0.1:5173](http://127.0.0.1:5173)

### Optional frontend API override

The frontend automatically targets the same host as the page and port `8000`.

If you want to point it somewhere else, create a frontend env file and set:

```bash
VITE_API_URL=http://127.0.0.1:8000/api/v1
```

## Example API Usage

### Upload documents

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/documents/upload" \
  -F "files=@/path/to/file.pdf" \
  -F "files=@/path/to/file.docx"
```

### Query documents

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/chat/query" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Summarize the key contractual obligations.",
    "document_ids": null
  }'
```

## Storage Notes

- Uploaded source files are stored in `backend/storage/uploads/`
- Chroma persistence lives in `backend/storage/chroma/`
- Document metadata is tracked in `backend/storage/documents.json`

These paths are local project data and are ignored by Git.

## Current Local Limitation

If uploads return `503 Service Unavailable`, the most common reason is that the configured model backend is not available yet.

For example:

- if `.env` uses `ollama`, Ollama must be installed and running
- if `.env` uses `openai`, `OPENAI_API_KEY` must be set correctly
